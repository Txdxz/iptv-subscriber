# IPTV 源每日自动筛选 + 固定 M3U 订阅服务

本项目针对目标网站 `https://iptv.cqshushu.com/index.php`，实现一套轻量、稳定、低维护成本的自动化服务。专为山西家庭用户设计，每天自动按特定优先级挑选最佳 IPTV 源，原子更新并对外提供始终不变的固定 M3U 订阅地址。

电视端只需在首次订阅时填写一次固定地址，后续每日由后台自动重新筛选更新，无需手动频繁更换订阅。

## 一、网站实际检查与逆向分析结果

在不绕过安全限制、不破解验证码、不编造任何假接口的前提下，我们实测获取到网站的真实运行机制：

1. **公开访问与安全机制**：
   - 网站首页 `index.php` 接受常规浏览器 User-Agent 的 HTTP GET 请求。
   - 对带查询参数的请求（省份筛选、分页、详情），前端脚本 `js/pae06.js` 提供了安全 Token 生成逻辑 `window.generatePaerToken(url)`。
   - 请求时附带 Headers：
     - `X-Requested-With: XMLHttpRequest`
     - `X-CSRF-TOKEN: <生成的Base64 Token>`
     - `Referer: https://iptv.cqshushu.com/index.php`
   - 后端返回标准的 JSON 格式：`{ status: "success", title: "...", html: "..." }`。
   - **本服务已完整复现并内置了该 Token 算法，无需引入庞大的无头浏览器（如 Puppeteer/Selenium），极低内存占用即可高速运行。**

2. **地区筛选与分页**：
   - 网站原生支持省份代码定向查询：山西为 `province=sx`，陕西为 `province=sn`（严格隔离），北京为 `bj`，天津为 `tj`，上海为 `sh`。
   - 分页参数为 `limit=10&page=1`。

3. **源信息与状态字段**：
   - 列表中每一行提供：IP、跳转参数 `p` 与 `t`、节目数、类型文本（如 `山西太原酒店 山西联通`）、上线时间、更新时间、状态。
   - 状态实测存在：`新上线`、`存活x天`（如 `存活1天`、`存活4天`）和 `暂时失效`。

4. **M3U 接口获取**：
   - 携带 Token 请求详情页 `index.php?p=${p}&t=${t}`，提取频道列表 `s` 参数。
   - 直接请求 M3U 接口：`https://iptv.cqshushu.com/index.php?s=${s}&t=${t}&channels=1&format=m3u`，即可直接返回标准 UTF-8 编码的 M3U 播放列表。

## 二、核心特性与设计原则

- **完整源替换**：只完整采用选出的单一最优源，绝不把多个源交叉混剪成一个大列表。
- **沿用存活源**：优先复检上期选出的源，只要在网站上依然保持存活（`新上线` 或 `存活x天`），立即停止当日全量筛选，继续沿用，避免电视频道频繁变动。
- **原子替换**：采用写入临时文件后 `rename` 机制，彻底杜绝网络中断产生的半写入或空文件。
- **全失败兜底**：若某天网站无任何可用源，系统自动保留旧版 M3U，并发出企业微信告警通知。
- **进程文件锁**：防止定时任务和手动触发并发竞争。
- **历史快照与回滚**：保留最近 7 次更新的历史备份，支持一键 CLI 回滚。
- **纯标准库零外部依赖**：仅使用 Node.js 核心模块，轻量安全，启动迅速。

## 三、优先级匹配与筛选规则

严格执行用户指定的 9 级优先级梯队，从高到低逐档匹配：

1. **P1**：山西太原 山西电信
2. **P2**：山西太原 山西联通
3. **P3**：山西其他城市电信（大同、临汾、吕梁、长治、晋中等）
4. **P4**：山西其他城市联通
5. **P5**：山西其他城市移动
6. **P6**：天津 天津联通
7. **P7**：北京 北京联通
8. **P8**：上海 上海电信
9. **P9**：上海 上海联通

### 筛选短路与排序逻辑：
- **同档位排序**：网站更新时间降序 > 节目数降序 > 稳定标识 `p` 升序。
- **高档优先**：一旦当前优先级档位找到并验证通过有效源，立即停止后续低档位的所有网络请求与验证。绝不因低优先级源节目更多而越级选择。

## 四、部署方案指南

### 方案 A：家庭 NAS / 软路由 / 局域网小主机部署（首选推荐）

> [!TIP]
> **为什么最推荐在家庭本地网络部署？**
> 山西电信/联通的部分酒店源和组播源对运营商内网或家庭宽带 IP 友好。家庭主机部署不仅速度极快、延时低，而且直接处于山西家庭宽带环境下，播放成功率最高！

#### 1. Docker Compose 部署（最简便）
将本项目文件夹放到 NAS / 小主机上，进入目录执行：
```bash
docker compose up -d --build
```
容器启动后，即可在局域网内直接访问服务提供的订阅地址。

#### 2. 直接运行（系统自带 Node.js 18+）
```bash
# 启动守护进程（含每日17:00定时筛选 + HTTP订阅服务）
node src/scheduler.js
```
如果需要后台常驻，可以使用 `pm2` 或 `systemd`：
```bash
pm2 start src/scheduler.js --name "iptv-subscriber"
```

### 方案 B：GitHub Actions 0 成本全自动部署（免服务器）

无需购买任何云服务器或开机 NAS，直接依托 GitHub 免费算力与 GitHub Pages 静态托管：

1. 创建一个新的 GitHub 私有或公开仓库（例如 `my-iptv-subscriber`），将本项目代码推送上去。
2. 进入仓库 **Settings -> Pages**：
   - **Source** 选择 **GitHub Actions**。
3. 工作流文件 `.github/workflows/update-iptv.yml` 已配置就绪：
   - 每天北京时间 17:00 (UTC 09:00) 自动触发运行筛选；
   - 也可以在 Actions 界面随时点击 **Run workflow** 手动触发；
   - 自动将 `current.m3u` 发布到 GitHub Pages。
4. 部署成功后，在电视端播放器中填入生成的固定订阅地址即可。

---

### 方案 C：云服务器 (VPS) 部署

适合需要在外网随时向多台设备分发订阅的场景：
1. 在服务器上运行 Docker 或 Node 进程（端口 8088）。
2. 可配合 Nginx 绑定域名并配置 SSL 证书：
   ```nginx
   location /iptv/ {
       proxy_pass http://127.0.0.1:8088/iptv/;
       proxy_set_header Host $host;
   }
   ```
3. 电视订阅地址：通过个人域名服务路由访问。
4. **安全保护建议**：在 `config.json` 中配置 `"auth_token": "your_secret"`，电视端订阅时带上 Token 参数，防止地址被未授权探测扫出。

## 五、电视端固定订阅地址配置

无论后台如何每日轮换更新，电视端播放器中填写的 M3U 订阅 URL 始终保持不变。

> [!NOTE]
> 具体订阅地址由您的实际部署环境决定。请妥善保管个人订阅地址，避免公开泄露。

### 电视端播放器设置建议（如 TiviMate / DIYP / 影视仓 / Kodi 等）：
1. **订阅刷新设置**：建议勾选“启动应用时更新播放列表”或设置“每日刷新频率为 1 次”。
2. **切换机制说明**：固定地址提供最新的 M3U 内容，但正在播放中的频道是否会自动断开重连取决于具体播放器内核，通常换台或重启应用后会自动载入最新列表。

### 3. 已知局限性与使用须知
1. **网络专属性**：网站收录的部分酒店源或组播源可能依赖运营商专网或特定网段。部署在山西本地家庭网络中通常能获得最高播放率；若部署在云服务器或 GitHub Actions，请说明其仅负责获取与验证 M3U 列表元数据，并不代表云端能直接播放所有内网流。
2. **电视刷新依赖**：固定订阅地址本身不会强制向电视机推流，电视端必须支持定周期刷新或启动时刷新。
3. **频率合规**：本系统内置防抖与缓存机制，每日仅在固定时间拉取有限页面，严禁大幅提高调度频率以避免给目标网站造成压力。
